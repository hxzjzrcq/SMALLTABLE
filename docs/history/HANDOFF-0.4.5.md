# SMALLTABLE 0.4.5 交接

> 历史记录，不作为当前维护指令；当前入口见 [README](../../README.md)。本文中的“当前”“本轮”和操作指令仅指当时版本。文中 `VALIDATION.md` 指当时的验证记录，现已由当前版本记录替换。

基于交付的 SMALLTABLE-v0.4.0-完整源码.zip，未合并 Kimi 专用部署流程，未部署。

## 已实现

先攻盘：所有玩家添加、修改、删除任意条目；名字和数字独立于棋子。共享排序方向，默认降序，可升序；同值按房间数组顺序，编辑不移动原有位置。每端独立展开或隐藏。没有投骰、回合、轮次或自动战斗功能。每项名字最多 128 UTF-8 字节，数字范围 ±1,000,000，支持小数和负数；最多 255 项。

直线画笔：鼠标/单指拖动预览，松开提交一次。没有中途广播；取消、切换模式、断线或桌面代次改变时丢弃草稿；第二根手指开始缩放也会取消画线。五种固定颜色、固定屏幕视觉线宽、自由落点，不吸附网格。选择模式点线条后删除，任何玩家可删任意线条；DM 可清空。最多 255 条；坐标复用房间边界。世界坐标保存，随相机平移缩放；“查看全部”包括画线范围。绘图层在棋子下方。

## 数据与边界

schemaVersion 从 1 升到 2，新增 initiative、initiativeAscending 和 drawings。parseRoom 严格验证 schema 1 后显式迁移，加载磁盘和恢复 ZIP 都使用它。schema 2 直接严格校验，未知版本拒绝。新存档无法由 0.4.0 回读；恢复旧备份会以该备份替换房间，因而新增两项为空。

共享模型与命令在 src/shared/model.ts。新增 initiative.put/delete/order 与 drawing.add/delete/clear，均校验 epoch，新增字段指令使用 strict。服务端保持串行变更、保存和角色投影；普通玩家不能通过新命令读写 DM 私有说明。先攻表与画线均进入快照、磁盘、ZIP 备份，不接触浏览器私人笔记或 DNDROLL 会话。

src/client/components/InitiativePanel.tsx 管理界面表单；controller.ts 为唯一网络接口。Board.tsx 扩展现有手势，区分本地测距与公开直线。所有 UI 操作只调用 SmalltableClient。

## 后续范围

继续挂起：图片限额、地图视角、刷新登录状态、正式部署密码与代理配置。本轮未引入自动掷骰、Token 绑定、当前回合、范围模板、自由曲线、所有权、撤销或拖动锁。Core 及依赖版本保持原样。

人工验收：电脑与手机分别打开先攻盘、修改数字并切换排序；手机隐藏不应影响电脑；画线后双端看到，切回选择模式删线；玩家不能清空，DM 可清空；导出并恢复备份，确认先攻与线条都回来。
